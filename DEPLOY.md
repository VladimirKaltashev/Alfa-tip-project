# Запуск на сервере

Нужен только Docker с поддержкой Docker Compose. Загрузите на сервер всю папку проекта и выполните в ней:

```bash
docker compose up -d --build
```

Приложение будет доступно по адресу `http://IP_СЕРВЕРА/`.

До первого использования создайте заведение и менеджера:

```bash
docker compose exec backend python -m backend.manage create-venue demo --name "Листва" --address "Москва" --username manager
```

CLI запросит пароль и повторный ввод (12–128 символов). Пароля по умолчанию нет, пароль не передаётся аргументом команды. Затем откройте `/manager?venue=demo`, войдите, добавьте команду и выдайте сотрудникам доступ в разделе «Доступ». Сотрудник входит через `/waiter?venue=demo`; гости открывают `/?venue=demo`.

Если в томе уже есть старая запись `demo`, сохраните её и создайте только менеджера:

```bash
docker compose exec backend python -m backend.manage create-user demo --username manager --role manager
```

Новое кафе создаётся той же командой `create-venue` с другим ID. Для восстановления доступа администратора используйте `reset-password <id-заведения> --username <логин>`: старые сессии отзываются.

Для локальной разработки задайте `ALFA_TIPS_DB` равным `./backend/local.sqlite3`, выполните те же команды через `python -m backend.manage`, затем `python -m backend.server` и `npm run dev` в отдельных терминалах. На этой Windows-машине Python доступен через WSL. HTTP backend слушает порт 8000, Vite проксирует API с 5173. Не используйте временную `.qa`-базу для рабочих данных.

Для внешнего HTTPS-развёртывания настройте TLS на reverse proxy и задайте `ALFA_COOKIE_SECURE=1` в окружении Compose. Нулевое значение — только для локального HTTP. [Подробности доступа и ограничения](docs/security.md).

Проверка состояния:

```bash
docker compose ps
curl http://127.0.0.1/healthz
```

Обновление после загрузки новой версии файлов:

```bash
docker compose up -d --build
```

Просмотр логов:

```bash
docker compose logs -f app
```

Если порт 80 уже занят reverse proxy, измените в `compose.yaml` строку `80:8080`, например на `8080:8080`.

## Состав развёртывания

`app` — Nginx со статическим React-клиентом; `backend` — Python API с SQLite. Том `alfa-tips-data` сохраняет базу между перезапусками контейнеров. Проверить API можно через публичный прокси:

```bash
curl http://127.0.0.1/api/health
```

Клиент сначала использует локальный кэш, а при наличии backend синхронизирует состояние через `/api`. Поэтому после запуска через Docker данные общие для устройств, открывших один и тот же сервер.

## Проверки и резервная копия

Перед обновлением выполните `npm test`, `npm run build` и `python -m unittest discover -s backend -t .`. Старая Windows-команда Python может быть недоступна; тогда используйте Python 3 в WSL. Контейнерная сборка выполняет серверные тесты самостоятельно.

Создание согласованной копии работающей базы (используйте новое имя файла при каждом запуске):

```bash
docker compose exec backend python -m backend.backup /data/backups/before-update-2026-10-30.sqlite3
docker compose cp backend:/data/backups/before-update-2026-10-30.sqlite3 ./before-update-2026-10-30.sqlite3
```

Утилита отказывается перезаписывать файл. Скопируйте результат с сервера в отдельное хранилище: файл внутри того же Docker-тома не защищает от потери тома. Не копируйте один основной файл живой SQLite вручную — подтверждённые изменения могут находиться в WAL.

Для проверки восстановления откройте копию в отдельном окружении с `ALFA_TIPS_DB`, указывающим на неё, и проверьте `/api/health`, историю операций и суммы. Переключение рабочего сервера на копию выполняйте после остановки записи, сохранив исходную базу и её WAL. Автоматического восстановления поверх действующих данных нет.

При обновлении схема мигрирует без сброса истории. Старые вкладки следует обновить; старые демо-сессии Alfa ID потребуют повторного входа. Сохранение устаревших данных получает 409 — это защита от перезаписи изменений другого устройства. Код и образ backend/client нужно обновлять вместе.

## Ограничения эксплуатации

Платежи, выплаты и банковский Alfa ID остаются демонстрационными. Роли, изоляция API и аудит реализованы, но это не заменяет внешний аудит безопасности, MFA, мониторинг, проверку нагрузки и подключение платёжного провайдера. Публичное развёртывание в рамках доработки не выполнялось.
