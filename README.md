# Альфа Чаевые

Репозиторий выпускной работы с Альфа-Банком.

Мобильный кликабельный фронтенд для банковского проекта чаевых. React 19, TypeScript, Vite. Создан на основе `Фичи.docx`, модели `Chaevui.archimate` и пяти референсов на доске Miro. Все исходные документы оставлены без изменений.

## Запуск

Нужен Node.js 22.6+ (проверено на Node.js 26).

```sh
npm ci
npm run dev
```

Открыть http://localhost:5173. С телефона в той же Wi-Fi сети: `http://<IP-компьютера>:5173`. QR-код использует текущий адрес страницы: для сканирования телефоном открывайте кабинет через сетевой IP, а не localhost.

```sh
npm run build
npm test
npm run preview -- --port 4173
```

## Демонстрационные данные

Оплата и вывод имитируются, без банковских SDK и реквизитов. Сбор настоящих карточных данных не предусмотрен. Доступ к ролям свободный для проверки прототипа. Название, адрес и счёт — редактируемые заглушки. Комиссия 0 ₽ задана только для демо, не является тарифом банка.

Общее состояние хранится в `localStorage` под ключом `alfa-tips-demo-v1`. Черновик оплаты — в `sessionStorage` под ключом `tip-draft`. Кабинеты синхронизируются между вкладками одного браузера и одного адреса через событие `storage`. Разные браузеры/устройства имеют отдельные данные. Демо-история заполняется относительно текущей даты.

Начальный состав: Александр (официант), Мария (повар), Максим (бармен). Количество сотрудников и роли не фиксированы: индивидуальные чаевые и разделение доступны для активных сотрудников из данных. При изменении состава предлагаются равные доли. Все суммы хранятся целыми копейками. Остаток округления распределяется по наибольшей дробной части; сумма сохраняется.

## Подключение бэкенда

`src/repository.ts` — граница данных; `src/model.ts` — типы и расчёты. Замените локальные функции адаптером API. Экран оплаты вызывает `confirmPayment`; для реального шлюза необходим серверный платёжный статус, а не доверие клиентской кнопке. Контракт и ограничения описаны в [docs/backend.md](docs/backend.md).

Реализованы клиентские сценарии. Не реализованы серверная авторизация ролей, реальные платежи/выплаты, SMS/push, CRM/касса и хранение данных между устройствами. Эти интеграции требуют бэкенда и реквизитов банка.

## Проверка

`npm run build` проверяет TypeScript и собирает production-версию. `npm test` проверяет равное разделение по умолчанию, миграцию черновиков и денежные расчёты, валидацию, сохранение отзывов, идемпотентность, распределение и вывод. Интерфейс адаптирован под 320–600 px и большие экраны, поддерживает клавиатуру, системное уменьшение анимаций и нативный фокус диалогов.

## Обновлённая страница гостя

Сверху — короткая строка заведения и адрес. Затем сумма → разделение → получатели → отзыв → способ оплаты. На всех экранах убран переключатель ролей: кабинеты открываются по своим адресам. После оплаты гость остаётся в своём интерфейсе.

Новый черновик по умолчанию делится поровну между активными сотрудниками; сумма чаевых не выбирается автоматически. В «Свои доли» проценты отображаются целыми. После ввода, например, 70% и 10% оставшаяся доля автоматически становится 20%. При выключении разделения выбирается первый активный сотрудник. В равном режиме округлённые суммы отмечены знаком «≈», а фактическое распределение сохраняет каждую копейку.

Старые неоплаченные черновики один раз переводятся на новый вариант распределения, сохраняя ID, сумму и отзыв. Последующий выбор пользователя сохраняется.

Ссылка «Оставить позже» сохраняет дату визита и сумму демонстрационного счёта в параметрах ссылки (`mode=later`, `visitAt`, `bill`). В таком сценарии под названием места появляется одна дополнительная строка. Контекст сохраняется при переходе к оплате и обратно. В боевом приложении эти данные нужно получать по ID чека с сервера, а не доверять URL.
