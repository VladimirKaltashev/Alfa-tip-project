# Ревизия прототипа, 23 октября 2026

## Продуктовое решение

Кабинет заведения начинается с привычной композиции Альфа-Онлайн: профиль, меню, «Мои продукты», поиск, сервисные карточки и быстрые действия. Чаевые — сервис внутри банковского окружения. Все разделы кафе используют одну оболочку; гостевая форма по-прежнему посвящена сумме, сотрудникам и оплате.

Референсы: локальные `скрины_альфа/главное_меню.png` и `предложение.png`. Официальные материалы: [приложение Альфы](https://alfabank.ru/apps/amobile/), [решения для ресторанов](https://alfabank.ru/sme/specialoffer/restaurants/), [нетмонет для бизнеса](https://alfabank.ru/sme/loyalty/offers/net_monet/). Они подтверждают уместность QR, индивидуальных и командных чаевых. Банковские тарифы, обещания доходности и реальные остатки в прототип не перенесены.

## Реализовано

- Единая оболочка кабинета, активный раздел, возврат на главный экран и мобильное меню.
- Поиск разделов с результатами, состоянием «ничего не найдено» и очисткой.
- QR для гостей, скачивание и копирование ссылки через существующий диалог.
- Сводка за сегодня, переходы в статистику, операции, отзывы и команду.
- Отметки прочитанного сохраняются на сервере; старый клиент не снимает отметку.
- Нераспределённые суммы не зачисляются при чтении локального хранилища. Распределение доступно в статистике и сохраняет сумму.
- Запросы сохранения упорядочены, ошибки синхронизации видны пользователю.
- После обнаружения API его отказ не приводит к скрытой локальной оплате. Сетевые ошибки и таймауты требуют повторной попытки с прежним ID.
- Пустая серверная база инициализируется один раз транзакционно.
- Исправлены ввод номера, проверка возвратного URL и описание хранения данных Alfa ID.
- Удалены неиспользуемые старые варианты экранов сотрудника и заведения.
- Исправлена проверка секретов в CI: условия шага используют переменные окружения согласно [документации GitHub](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets).

## Проверка

Production-сборка, 32 теста клиентской модели и 8 серверных тестов проходят. Серверные тесты запущены в Python 3 через WSL. Визуальная проверка в Chrome не завершена: запрос инструмента на доступ к окну истёк. Адаптивная вёрстка реализована, но её внешний вид на устройствах ещё нужно проверить.

## Что остаётся до реального сервиса

Это учебный прототип. Роли не защищены серверной авторизацией, API общего состояния открыт, бонусы общие для демо. Для работы с настоящими пользователями нужны изоляция заведений и гостевых историй, отдельные серверные команды вместо записи всего Store, авторизация владельца и сотрудников, договор интеграции с платёжным провайдером и Alfa ID, серверное подтверждение платежей, аудит и кассовая интеграция. Публичный production-деплой в рамках ревизии не выполнялся.

Состояние разных устройств загружается при открытии страницы. Одновременное изменение профилей пока имеет семантику последней записи. Следующий технический этап — версионирование изменений и отдельные операции API; автоматический опрос всего Store до этого может перезаписывать локальные несохранённые правки.
